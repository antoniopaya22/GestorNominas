# Git Commit & Push

Ejecuta el flujo completo de commit + push siguiendo Conventional Commits.

## Reglas críticas

- ❌ NUNCA añadir:
  - "Co-authored-by: Claude"
  - "Generated by Claude"
  - cualquier referencia a Claude como autor
- El commit SIEMPRE debe parecer 100% humano

## Pasos

1. git add -A

2. Revisar cambios:
   - git diff --cached --stat
   - git diff --cached

3. Extraer ID (ClickUp/Jira/etc) desde branch

4. Validación:
   - pre-commit si existe
   - tests si aplica

5. Generar commit:

Formato:
<type>(scope): descripción corta

<cuerpo detallado>

Tipos:
feat, fix, docs, style, refactor, perf, test, build, ci, chore

Reglas del título:
- Español
- Imperativo
- < 72 chars
- sin punto final
- NO mencionar IA ni Claude

Reglas del cuerpo (OBLIGATORIO, salvo cambios triviales de una línea):
- Español, en párrafos y/o bullets (`- `)
- Explica el QUÉ cambió (lista los componentes/archivos relevantes y su rol)
- Explica el POR QUÉ (motivación, bug que se corrige, contexto del CU/ticket)
- Explica el IMPACTO (qué se rompía antes, qué se valida ahora, riesgos si aplica)
- Si hubo merge/revert, indica explícitamente qué commit(s) se integran o revierten
- Tan extenso como sea necesario para que alguien sin contexto entienda el cambio sin mirar el diff
- NO mencionar IA ni Claude

6. Mostrar commit

7. git commit

8. Manejar errores de hooks

9. git push
